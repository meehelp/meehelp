# Content evidence ledger

Generated by `npm run evidence` from `src/data/evidence.ts` — edit that file, not this one.

This tells future sessions **which product facts are grounded in code and which are assumptions**.
Sources were read **read-only** (Phase 4.5) from MeeHelp_User_App, MeeHelp_Helper_App, MeeHelp_Backend, meehelp-admin
and the 2022 legacy apps. Only source code and customer-visible app copy were used — no database records, personal
data or credentials. Most catalogue values (category/task names, prices, plan sets, cities) live in the production
database and are **not** known from code.

## How to use it

- Website copy may state an app mechanic only through `src/data/product-facts.ts`, citing items below.
- `publicSafe: no` items are internal (tuning values, negative findings used as guards) and must never be published.
- `requiresBusinessApproval: yes` items are grounded in code but still need sign-off before a page using them goes live.
- Confidence: **high** = exact string or hardcoded value seen; **medium** = inferred (e.g. task names from icon IDs) or
  partly server-driven; **low** = weak signal.

## Notes and caveats

- `biz.models`: Business confirmation. The code only partly reflects it — see impl.* items and CONTENT-EVIDENCE.md 'Implementation vs confirmation'.
- `biz.plans`: Code serves plans from the `plan` table with an even/odd user A/B split (MeeHelp_Backend customer.php ~489-533). The app onboarding text 'Plans start at Rs 299' (User App onboarding_screen.dart:29) does not match the confirmed lowest plan (₹499).
- `mkt.part-time-hours`: Also helper side: lib/screens/auth/create_account/update_details_screen.dart 190-205 (Helper App). App copy: 'Hire 2 hours to 12 hours house helper from locations near you' (onboarding_screen.dart:24).
- `mkt.full-time-live-in`: Helper option 'Fixed Full time work (24 hr customer k ghar par Rehana)'. User App: 'No more paying high brokerage to hire live in helpers. Talk directly with helpers, negotiate and hire.' (app_localization.dart:49).
- `mkt.preferences`: House size appears for the cleaning work type, household members for the cooking work type (IDs 6/5 — meaning inferred, medium).
- `mkt.no-filters`: Negative fact used as a guard: Website V2 must never claim these filters exist (claims.ts unsupportedClaimRules).
- `mkt.search-radius`: Internal tuning value; not published. The site says only that full-time (live-in) search looks further afield — and even that is not stated today.
- `mkt.profile-fields`: Profiles do not show expected salary — salary is agreed with the helper. A rating is also shown but defaults to '5' when a helper has none (helper_profile_screen.dart:210), so ratings are never used in marketing.
- `mkt.contact`: Backend: viewing inserts rt_view_provider once per helper; purchases set allowed_view_provider (customer.php ~13488-13515, ~2261-2280).
- `mkt.interview`: Server supports it; the current customer UI path was not traced end to end, so the site only says 'discuss and arrange a trial'.
- `mkt.no-trial-feature`: Site copy always words the trial as something you arrange with the helper.
- `mkt.employer-checks`: Contradicts nothing the site says (the site never claims police verification), but sits uneasily beside the approved 'Aadhaar verified' wording — see open question Q-VERIFY.
- `mkt.free-view`: Promotional and dynamic (Phase 4 brief): never in evergreen copy. Kept in src/data/promotions.ts.
- `cat.helper-categories`: No 'Elder Care' helper category exists in the helper app or the 2022 helper app (Expected Work: Cooking, Cleaning, PatientCare, BabyCare — helper/lib/user/create_account_page_two.dart ~716-841). Elder-care marketplace pages are HOLD pending confirmation (Q-ELDER).
- `cat.task-names-server`: So detailed task lists on Website V2 are general descriptions of the role, not a copy of the app's task list. They need business review.
- `od.otg-tasks`: 'Please select at least 2 cleaning services before continuing.' is exact (high). Task names are inferred from icon IDs 75-80 (medium). Laundry offers machine or hand wash.
- `od.otg-durations`: 60 and 90 min options are commented out in the app but still priced in the backend (customer.php 131-147). Treated as the current minimum duration (120 min) for one-time cleaning.
- `od.otg-book-now`: Backend: 'Available between 7:00 am to 8:00 pm only.' (customer.php:14582).
- `od.no-materials`: Server text with this exact fallback; also schedule_date_time_widget.dart:321 and backend customer.php ~8013.
- `od.hourly-tasks`: Task IDs 32-47 and 81-90 mapped to icons (babyCareIcon=37, elderCareIcon=38, patientCareIcon=39). Names are inferred from icons; the live names come from the server.
- `od.hourly-durations`: Slot table is hardcoded: e.g. 07:00 allows [2…12] hours, 19:00-20:00 allow [2] only.
- `impl.instant-scope`: The business confirmed instant booking for all five categories. Until the app shows it, Website V2 copy for babysitter, elder care and patient care describes scheduled booking only (Q-INSTANT).
- `od.cook-hourly`: Cooking also appears as a one-time task (icon 79). Members 1–5 drive price (backend rt_member_new_price).
- `od.gender-pref`: Charge amount comes from the server (fallback ₹100) — not published.
- `od.details-after-payment`: Backend: 4-digit job OTP verified before the job moves to In-Progress (customer.php ~10724, ~12753-12795). Helpers also upload a selfie before the start OTP (Helper App home_controller.dart ~332-337).
- `od.payment-split`: Exact split depends on server commission settings and a city-level 'commission-free' mode. Not stated on the site until the business confirms the wording.
- `od.pricing-unknown`: Hardcoded cleaning price table is non-monotonic (120 min cheaper than 90 min) and the app shows different GST fallbacks (5% vs 18%). On-demand prices therefore stay UNKNOWN on Website V2.
- `od.cancellation`: Pre-acceptance policy text comes from the server; backend policy copy has more windows (customer.php ~8005-8075). Not published until the business gives one authoritative policy.
- `od.no-tracking`: Guard: the site must not claim tracking or SOS.
- `trust.mobile-otp`: Approved wording 'Mobile number verified by OTP' (src/data/verification.ts).
- `trust.aadhaar`: Approved wording 'Aadhaar verified'. Caveats for the business: the upload endpoint sets the verified flag on upload (provider.php ~768-812) and the in-app Aadhaar-OTP screen is commented out; admins can also verify manually. 'Only verified profiles will get orders.' applies to on-demand orders. The customer app shows no verification badge.
- `trust.address`: Supports the approved 'Current address on record'. A separate PERMANENT address is not visible in the current helper app (one address only; backend has staying_currently/current_city fields). Q-ADDRESS.
- `trust.liveness`: Not yet in the approved verification list — candidate for approval.
- `trust.no-police`: 'Meehelp will conduct the basic document verification which does not include police verification.' Consistent with the current guidelines (mkt.employer-checks). Police/background claims stay blocked.
- `trust.ratings-default`: Reason ratings, review counts and AggregateRating stay off Website V2.
